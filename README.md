# GSB Bugfix Task
## 题面
内容中台的栏目权限又出事了。运营只在一个子栏目上被授了只读，整棵子树却都能打开；外包角色的边界写的是只读，写操作照样通过；栏目删进回收站后管理员还能删数据；角色继承表里出现环，服务启动直接卡死；同一身份对同一栏目连查两次，结果还会变。请重写 nested_role_tree.py 里的 RoleTreeGuard：初始化时接收一份包含角色、栏目、动作、授权和拒绝的策略；角色沿父角色递归收集权限，授权落在动作和栏目上，只向下覆盖后代，不能影响祖先；链路上任何一层拒绝都压过允许，并说明命中的角色和节点；角色声明了边界时，越界授权作废；角色图或栏目树成环、未知角色、未知动作、未知节点、空身份都要有稳定结果或带错误码的异常；软删除节点连同后代一律拒绝。查询结果给出是否允许、原因、角色和节点，原因只用 grant、deny、boundary、deleted、no_grant、no_roles；另一个方法返回该身份在节点上可做的动作集合，状态查询给深拷贝。动作区分读、写、删除、分享，通配只留给管理员；节点用父指针组织，根节点没有父级；边界是动作清单，没列出的动作即使有授权也不算；返回的节点名用调用方传入的那一个，不能回写内部结构；多个守卫实例共用同一份策略时不能互相污染；动作集合去重后按字典序排列；拒绝同时命中多个角色时只报最先命中的一条；查询结果不能把内部策略对象直接交给调用方，同一身份重复查询要返回内容相等但彼此独立的对象。仓库自带的十五个测试现在全红，测试不要动；我还会用八个线程反复查询，结果不能漂移。
