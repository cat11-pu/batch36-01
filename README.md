# GSB Bugfix Task
## 题面
对象存储开放跨账号访问后，安全团队复现出一条奇怪的链路：同账号里资源策略单独给了读权限，请求却因为身份策略没写而被拒；跨账号只改身份策略就能读到对方桶；权限边界写成允许列表，结果被当成额外的允许叠加；会话策略里的拒绝没有生效；排除动作被当成普通动作字符串，删除操作反而通过了。请重写模块 iam_policy_decider 中的 IamDecider：构造时传入身份策略、资源策略、权限边界和会话策略四份文档，语句按云厂商风格写效果、动作或排除动作、资源或排除资源、主体和条件。动作与资源允许星号和问号通配；效果只认允许和拒绝，显式拒绝在任意一层出现都立即拒绝；同账号请求只要身份策略或资源策略有一边允许即可；跨账号请求必须身份侧和资源侧同时允许；权限边界和会话策略都是上限，身份策略允许但上限没允许就不能通过，上限里的显式拒绝同样生效；排除动作里的动作不匹配该语句，排除资源里的资源同样排除。条件支持字符串相等、字符串通配、字符串不等、布尔、网段属于、网段不属于和资源名通配，键从请求上下文取，缺键按假处理。判定结果返回是否允许、原因和命中语句下标，原因取显式拒绝、身份允许、资源允许、无允许和边界拒绝；请求缺主体、动作、资源或策略结构不合法时抛带错误码的异常。随包十五条用例目前全部失败，测试文件不许改；同一请求重复判定结果要稳定相同。策略文档必须是字典，版本只认两个固定值，语句必须是非空列表；单条语句里动作与排除动作不能同时出现，资源与排除资源也不能同时出现，主体只在资源策略里生效；匹配大小写敏感，问号只匹配一个字符，星号可以跨斜杠；请求账号必须与主体账号段一致，不一致按请求非法拒绝。

```bash
python -m pytest tests -q
```
