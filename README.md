# GSB Bugfix Task
## 题面
网关对外开放以后，合作方开始用双向 TLS 接进来，身份映射接连出事。证书链根本没看签发者，随便一张自签证书都能过；信任集合为空时统统放行；只带服务端用途的证书也被当成调用方身份；密钥用途里没有数字签名照样放行；证书过期和尚未生效都只写进日志；中间证书挂了三层也不拦；证书缺链路深度字段时按零处理，深层链混过去；主体常用名不在账号表里，代码却回退到证书里的组织字段；账号已停用仍然签发会话；标识串里的工作负载名称和账号登记值不一致也通过；账号表里的地址前后带空格，比较时没有裁剪；序列号是空字符串，直接进了缓存键；吊销名单里的序列号从来没有被查询，按字符串比较时大小写不同就漏检；请求携带的连接序列号和证书对不上，中间人替换证书也能继续；同一条连接上前后两张证书序列号不同也能复用会话；反向代理塞进来的头被无条件信任；有效期起止颠倒时算出负数剩余时间还往下走。mtls_gateway.py 的 MutualTlsAuthenticator 要求：签发者指纹必须命中信任集合，用途只认客户端认证，密钥用途必须包含数字签名，当前时间落在有效期内，链深度不超过上限，序列号非空且未被吊销，主体常用名精确映射到启用状态的账号，标识串与账号登记值逐字相等，账号标识前后空白先裁剪再比对，请求携带的连接序列号必须与证书一致，缺失 TLS 证书时不得采信转发头。返回主体快照。十五条用例现在全红，不能改测试。

## 运行方式

```bash
python -m pytest tests -q
```
