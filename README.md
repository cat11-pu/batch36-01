# GSB Bugfix Task
## 题面
移动端启用刷新凭据轮换，风控发现一批账号在两地同时续期。用过的旧凭据再交一次，服务端又发一整套新凭据；家族关系没有落地，泄露后只能逐个拉黑；有的凭据过期三天照样能换；客户端对不上也放行；续期时把只读扩成读写没人比对；主体被换成另一个工号；一批签发里权限重复出现，记录越滚越大；家族连续换几十轮没有尽头，老凭据一直留在链上；拉黑整个家族后，链尾凭据仍可用；查询接口把内部记录原样交出去，调用方随手一改就把到期时刻推后；两路请求同时拿同一凭据续期，两路都成功。refresh_rotation_store.py 的 RefreshRotationStore 负责这套轮换：签发时去重并规范化权限，登记客户端、主体、家族与到期时刻；轮换要核客户端一致、未过期、家族未拉黑，权限只许收窄；旧凭据再次出现按泄露处理，整族立刻作废并报专用错误；家族长度设上限，超了要求重新认证；查询返回副本且只给摘要与状态，不吐出可直接用的凭据；旧凭据保留已用标记供审计；签发时客户端或主体为空、权限不是列表都按参数错误拒绝；家族编号由服务端生成，重复时拒绝签发；并发轮换同一凭据只容一个赢家；家族与凭据的映射要能随快照恢复，不能只放在临时变量里；轮换失败时不能消耗旧凭据，成功后才标记已用；同一家族里的权限集合只能逐次收缩，去重不能打乱首次出现的顺序；错误码要区分未知凭据、过期、客户端不符、重放与家族已废。仓库自带十五条用例全红，测试不可修改。

## 运行方式
```bash
python -m pytest tests -q
```
