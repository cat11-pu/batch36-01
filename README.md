# GSB Bugfix Task
## 题面
安全运营在日志里发现同一枚通行密钥的签名计数来回跳。计数器持平的两次认证都被当成正常，克隆认证器毫无阻碍；计数下降时只打了一行警告，凭据继续可用；签名验证失败的请求也把计数写进了库；未知凭据编号被当成新凭据自动登记；计数器为零的老式认证器被直接拒绝，兼容性投诉一堆；同一凭据换一台终端上报，服务端没有比对绑定关系；计数一次跳升几千，没有任何异常标记；被判定克隆后，后续请求仍然放行；运维想恢复被隔离的凭据，接口允许把基线改低；恢复之后第一次认证计数又倒退，也没有再触发隔离；状态查询返回的内部对象被调用方改掉，告警列表被清空；两个请求同时带着同一个新计数进来，两个都成功。counter_clone_watch.py 的 CounterCloneWatch 负责计数监控：注册时绑定凭据与终端，重复注册拒绝；验签失败直接拒绝且不改状态；计数为零按不支持计数的认证器处理，保持原基线；非零计数必须严格大于该凭据基线，持平或下降判为克隆并隔离；跳升超过阈值要记录异常但仍接受，告警里带上发生时刻与旧基线；隔离后一律拒绝，不能自动恢复，恢复只能由显式调用完成且新基线不得低于旧基线；状态查询要返回当前基线、状态和告警列表；注册时凭据编号或终端编号为空直接拒绝，计数必须是整数且不能为负；同一凭据的基线只增不减，隔离状态要能被状态查询看到；恢复请求里的终端编号必须与注册时一致；快照深拷贝。十五条用例全红。

## 运行方式
```bash
python -m pytest tests -q
```
