# GSB Bugfix Task
## 题面
机房统一认证切到 Kerberos 后，跨时钟源的机器开始互相踢人。票据起始时间比本机快四十秒就被判无效，可另外几台慢五分钟的机器又能通过；认证器里的时间戳停留在昨天，服务端只看了票据有效期；同一份认证器被中间人录下来重放，日志里出现两条一模一样的记录；有人把服务主体写成 HTTP/app.example.com 少了领域后缀，仍然拿到了服务；客户端字段和票据里的用户名对不上也没人管；校验和为空照样通过；过期票据只要还在可续期截止时间之前就被无限续期；同一用户在同一秒发起两次请求，第二次被误判成重放；票据标志列表里混入未知值也没人校验；会话密钥为空字符串仍然放行；服务主体的大小写和斜杠顺序没有规范化，同名服务出现两种写法；重放缓存从不清理，进程跑久了内存一路涨。kerberos_ticket.py 的 KerberosTicketGuard 要实现票据验收：客户端与服务主体的领域必须一致，服务主体必须精确命中白名单；票据起始和结束时间允许 max_skew 的时钟漂移；认证器时间与本机时间差不能超过 max_skew，客户端必须和票据一致；重放缓存按客户端、服务主体、秒级时间戳和微秒序号去重，窗口内重复直接拒绝，不同微秒序号视为新请求；校验和为空要拒绝。renew 只对带可续期标志且未超过截止时间的票据生效，返回新的起止时间；不可续期的票据直接拒绝；续期窗口已过的票据也不能续。会话密钥必须非空，票据标志只接受已知集合，重放缓存要按窗口淘汰旧记录。15 条用例当前全部失败，测试不可修改。

## 运行方式
```bash
python -m pytest tests -q
```
