# GSB Bugfix Task
## 题面
内部 CA 做完交叉签名后，边缘节点开始间歇性握手失败，同一张服务端证书在两台机器上结论相反。路径构建只看 issuer 字符串，两个同名中间证书谁先出现就用谁，一条链走不到根也不回头；信任锚只比对了主题名，同名的另一把密钥被当成根；中间证书的 pathLen 写着零，下面还挂了一层没被拦住；根上配置的 DNS 许可域只检查了叶子，中间 CA 自己的备用名越界也放行；排除域里列出的内网后缀仍能签出证书；叶子证书只带客户端用途也被拿去跑服务端；未知的关键扩展被静默跳过；有效期按闭区间处理，到期当天仍被信任；签名关联拿错了父证书的公钥；候选父证书里混进终端证书也被当成 CA；叶子没有备用名时名字约束整段跳过；同一路径被重复展开，深链直接把栈打爆；锚证书本身过期也没有判断；不同候选路径的审计记录互相覆盖；链深度限制从未执行。chain_build_audit.py 里的 ChainBuilder 负责从叶子出发构建到信任锚的完整路径：按签名关系而不是名字找父证书，同一层有多个候选时优先最短路径并按指纹排序保证确定性；锚必须主题与公钥指纹同时命中；逐级检查 CA 标志、路径长度、有效期、关键扩展和用途；有效期按左闭右开处理，没有备用名按空集合处理而不是跳过约束；所有上级 CA 的名字约束都要作用到其下每一张证书的 DNS 备用名；同一指纹在一轮搜索里只展开一次；无路可达、锚不匹配、链条成环、深度超限分别报不同错误码。构建记录要能通过 audit 取出，且是隔离副本。仓库十五条用例目前全红，测试不许改。

```bash
python -m pytest tests -q
```
