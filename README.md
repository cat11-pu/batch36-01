# GSB Bugfix Task
## 题面
单点退出接上第二家 SP 后，用户反馈退出不彻底，也有人说自己被误踢。退出请求的签发方写成别家也照做；目的地址只比了主机名，测试环境的请求打到生产也执行；NotOnOrAfter 已经过去半小时仍被接受；请求编号为空或者重复出现，服务端没有登记；签名节点缺失、验签钩子返回假，流程照样清会话；会话索引列表里混进一个不存在的值，代码把能删的先删了，留下半截状态；列表里混入别人的会话索引，也一起清掉；一次请求携带的索引全部属于同一主体这个前提从没校验；响应里的 InResponseTo 抄错，SP 侧对不上；响应状态永远是成功，哪怕一个会话都没删；请求编号用过一次还能再用；退出服务返回的会话表被外部改坏，后续请求读到脏数据；两个 SP 同时提交同一个请求编号，两边都返回成功。saml_slo_dispatcher.py 的 SamlSloDispatcher 要实现 SP 发起的单点退出：签发方与目的地址逐字匹配，签名必须为真，NotOnOrAfter 必须晚于当前时刻，请求编号非空且一次性；会话索引列表不得为空，全部必须存在且属于同一主体，否则整单拒绝、一个都不删；成功时返回被移除的索引与被保留的索引，被保留的索引要说明属于哪个客户端；响应必须引用原请求编号，状态按实际处理结果给出；快照为深拷贝，调用方清空返回的会话表不能影响内部记录；退出请求里的 NameID 先去空白再比对，纯空格不算合法主体；请求时间字段是整数才接受，字符串数字不能蒙混；被拒绝的请求不得在会话表里留下半截改动；同一请求编号在并发下也只能被处理一次。十五条用例现在全红。

