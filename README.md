# GSB Bugfix Task
## 题面
资源服务器统一改走内省接口后，网关日志里冒出几种反常情况：已经过期的访问令牌查询回来仍是有效；兄弟租户签发的令牌只验了签名没看受众，也被判为可用；调用方不带客户端凭据照样能查；token_type_hint 传了乱码，接口直接抛五百。更麻烦的是，内省返回的那份字典被调用方改过之后，下一次查询拿到的是脏数据；令牌在缓存有效期内被吊销，缓存仍旧吐旧结论；scope 本来是列表，返回时被拼成逗号串；未知令牌居然回带 subject 和 scope，等于替攻击者确认了格式；客户端密钥按明文比较，长度不同就提前返回；签发时间在未来、过期时间早于签发时间都没人管；签发方是空串也算通过；并发吊销和内省撞在一起，两个调用方看到相反结果。introspection_broker.py 里的 IntrospectionBroker 负责这套内省：先验客户端身份与密钥摘要，再验令牌签名、签发方、受众、有效期与类型；失效、未知、签名不过一律只回 active 为假，不能夹带其他声明；有效结果按令牌摘要缓存，吊销当即失效；每次返回深拷贝；hint 只是提示，写错类型不应影响判定；未知 hint 值按非法参数处理；客户端编号未知时按鉴权失败处理，不能把内部异常抛成堆栈；缓存键用令牌摘要而不是原文；快照里只出现摘要，不出现可直接使用的令牌；调用方给的受众集合为空时拒绝启动，令牌里的 scope 不是列表按非法令牌处理；客户端密钥表里没有的编号直接拒绝，受众比较要区分协议与端口。仓库里十五条用例现在全红，测试文件不许改，实现也不许读取测试常量。

## 运行方式
```bash
python -m pytest tests -q
```
