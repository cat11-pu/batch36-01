# GSB Bugfix Task
## 题面
编辑器把用户草稿序列化成带类型标签的文本存在客户端，恢复时整段回传服务端。上线后有人改掉标签就让服务端加载了不该存在的类型，超深嵌套把进程栈打穿，重复键让前后两个值悄悄换掉，非有限浮点数混进金额字段，签名校验放在解析之后，畸形内容先被解析器吃掉再报错。draft_snapshot_reader.py 中的 DraftSnapshotReader 收紧恢复过程。创建时提供允许的类型名与校验函数、密钥、最大深度、最大条目数、最大文本长度。信封只能有正文和签名两个字段，签名只收小写十六进制；先核对签名再解析，签名不对时正文再畸形也只报签名错误；正文只收标准 JSON，重复键、非有限数值、越界整数分别报错；对象键必须是字符串，下划线打头的键一律拒绝；带标签的节点只能有标签和值两个键，标签须在允许集合内，校验函数返回假值即判值非法；数组长度、字符串长度、嵌套深度都受配额约束；恢复结果只有基本类型、列表、字典和标签转换后的值，不得出现可调用对象；正文体积超限在解析前拒绝。计数视图给出成功、拒绝两项和最近错误码，返回副本。验签要用恒定时间比较，标签名区分大小写，标签节点转换后保留类型名与值。同一信封重复读取结果一致。附带的十五个测试眼下全部报错。

## 运行方式
```bash
python -m pytest tests -q
```
