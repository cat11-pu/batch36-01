# GSB Bugfix Task
## 题面
运维批量更换堡垒机主机密钥，客户端开始报中间人警告：新密钥发布后旧密钥立刻被删，滚动窗口内的连接全部失败；同一代里重复指纹没有拒绝；两台不同主机发布了同一把密钥，清单照收；代次从一跳到三、或者退回旧代次，都能写入；发布时密钥列表为空也成功；密钥有效期起止颠倒也能落库；发布记录里同一代次的指纹顺序被调用方随意改；客户端 known_hosts 里混进别的主机键，评估时被当成自己的；客户端列表为空反而返回当前；已被撤销的键仍然返回可用；主机只剩一把键时也能撤销，节点直接失联；合并更新时把服务端没发布的键塞进来，客户端照单全收，连已撤销的键也加回来；键数量超过上限没有处理；过期键与新键同时存在时，评估结论反复横跳；主机名前后带空格被当成两台不同的机器；评估返回的键列表就是内部对象，改一下就污染后续判断；撤销不存在的指纹被当成成功；快照能被调用方改到内部代次。ssh_hostkey_rollover.py 的 HostKeyRolloverLedger 管理这套轮换：发布时代次从一递增且每次只加一，同代指纹去重，跨主机指纹唯一，密钥列表非空且有效期不倒挂；主机名去空白后比较，空名拒绝；评估客户端按键时区分当前、可更新、已撤销、已过期、未知主机键与外来键，空列表单独报错，返回值是副本；合并只接受本机已发布且未撤销的指纹，活动键按服务端顺序在前，仍在重叠期内的旧键保留在后，总数不得超上限；撤销不能清空最后一把可用键，重复撤销单独报错；快照是深拷贝，只保留指纹和代次。十五个测试现在都红。

```bash
python -m pytest tests -q
```
