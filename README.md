# GSB Bugfix Task
## 题面
云盘的所有权转移上线后，客服每天收到互相矛盾的工单：编辑者把别人的文件转给了自己，系统只看他有没有写权限；发起转移后原属主立刻失去访问，接收人却还没点确认；两个管理员同时点确认，文件被转了两遍；待处理的转移过期后还能接受；只读共享的用户能删文件；已进回收站的对象仍能被管理员操作；管理员没有任何凭证就能直接接管。请重写模块 ownership_transfer_ledger 中的 OwnershipLedger：构造时传入对象表和用户表，对象记录属主和删除状态，用户记录管理员标记。共享只允许属主调用，级别只认只读和可写，被共享人必须存在；发起转移只允许属主，目标不能是属主自己，对象不能已删除，有未完成转移时不能再发起第二个，返回转移编号；接受转移只能由目标用户在有效期内调用，成功后属主改为目标，旧属主失去所有权限，重复接受或过期接受报错；权限查询判断某人对某对象的读、写、删除、共享、转移权限，已删除对象全部拒绝；管理员必须带非空事故单号才能越过属主检查，没有单号一律返回假。失败时抛专用异常，错误码区分非属主、非目标、级别非法、转移待处理、转移过期和转移已结束。随包的十五个用例眼下都红着，测试保持原样；并发接受同一张转移单时只能有一个成功，另一个必须报错。对象和用户表在初始化时做快照，之后外部修改不能影响账本；接受成功后旧属主不能再共享或发起转移；共享记录跟随对象保留，但原属主自己那条要清掉；待处理转移只能有一个，同一目标重复发起返回原单号；转移单要有唯一编号、对象、原属主、目标、创建时间和过期时间。

## 运行方式
```bash
python -m pytest tests -q
```
