# GSB Bugfix Task
## 题面
单点退出改成前端通道广播后，门户里出现退不干净的会话。iframe 地址用的是明文协议，浏览器按混合内容拦掉后日志却记了成功；签发方参数只判断非空，任意身份提供方都能触发退出；会话标识在多个应用之间复用同一个值，退出一个应用时把别的应用也带下线；来源页不在白名单里也照样清会话；缺少会话标识的请求被当成全量退出；iframe 连续加载两次，第二次返回成功但绑定早已不存在；注销地址自带查询参数时，拼接后原参数被覆盖；同一编号登记两次，旧回调地址被换掉；注销地址带井号片段，片段被忽略；会话过期后仍能构造出 iframe；退出一个客户端后，同一会话在其他客户端的绑定还在，但全局登出没有清干净；iframe 缺少防缓存参数，防缓存失效；回调域名写成通配符也通过；注销地址指向外部域名时没有做归属校验；查询参数拼接顺序不稳定。frontchannel_logout.py 的 FrontChannelLogoutHub 负责客户端登记、广播地址生成和回调处理：客户端编号唯一，注销地址必须是 https 且不带片段，回调域名白名单不能含通配符；广播时为每个客户端生成独立的、至少三十二位的十六进制会话标识，保留原有查询参数，按参数名排序并附加一次性防缓存参数，签发方和会话标识都要做百分号编码；会话不存在或已过期时拒绝生成；处理回调时签发方必须精确命中，会话标识必须属于某个客户端且未被消费，来源页主机要在该客户端白名单内；只清除对应客户端的绑定，重复回调返回已退出状态而不是报错；全局登出要清空该会话的全部绑定，之后任何回调都按未知会话处理。仓库自带 15 条断言眼下全部是红的，测试文件不得修改。

## 运行方式
```bash
python -m pytest tests -q
```
