# GSB Bugfix Task
## 题面
密钥管理平台把单钥改成主备双钥后，故障演练发现回滚路径不通：备钥还没提升就被拿去加密；两次提升间隔不到下限也成功；安装后没有记录安装时刻，最小间隔从零开始算；提升后旧主钥立刻失效，正在解密的历史任务全部报错；宽限期过了旧钥还能解；宽限期配置成负数也接受；显式退役的主钥又被解密接口放行；备钥版本号比当前主钥小也能安装；版本号写成字符串数字也被当成有效；一个密钥编号同时挂到两个版本；主钥被判定泄露后，旧密文依旧可解，加密接口还继续用主钥；泄露标记之后还能把已泄露版本提升回来；备钥还没就绪时主钥泄露，系统没有停在安全状态；解密遇到未知版本返回空串；提升尚未安装的版本却把备钥清掉；并发安装两把备钥都成功；快照把密钥材料带出去，宽限截止也没有随快照恢复。dual_key_secret_rotation.py 的 DualKeyRing 负责双钥生命周期：安装的版本号必须是整数且严格递增，密钥编号全局唯一，同一时刻只允许一把备钥，并发安装只能有一个成功；提升要检查备钥存在且距上次提升不短于最小间隔，成功后原主钥进入只解密状态并给出宽限截止；宽限期必须非负且不得越界；加密只走当前主钥；解密接受主钥与宽限期内旧钥，宽限外、已退役、已泄露、未知版本的一律拒绝；退役不能作用于主钥，重复退役给出独立错误码；泄露标记立即生效且不可撤销，已泄露版本禁止再提升，之后必须显式提升备钥才能恢复加密；快照是深拷贝，里面不出现密钥原文。这组十五个测试眼下都是红的。

```bash
python -m pytest tests -q
```
