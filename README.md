# GSB Bugfix Task
## 题面
人事系统改用 SCIM 2.0 向目录推人，第一批就出问题。幂等键相同的重复请求创建了两个账号；externalId 相同但幂等键不同时，本应更新却新建了第三条记录；PATCH 的替换操作直接改掉了登录名，后续认证全部对不上；版本号落后的修改覆盖了别人刚提交的内容；删除操作把必填的登录名摘掉后，资源只剩一个空壳；向多值属性追加已有值，读出来翻了倍；请求体里的租户字段能把用户写到别的租户；分页起始序号传零时返回了全量数据；每页条数传一千也没有被截断；被停用的用户仍然出现在默认列表里；重复停用返回内部错误而不是幂等结果；停用后再推送同一外部编号，新资源没有复用原来的主键；未知的 PATCH 操作符被静默忽略；响应里把内部密码字段一起回显；调用方拿到返回对象后改动，影响了库里的记录。scim_directory.py 的 ScimDirectory 要实现入站供应：创建以外部编号为业务唯一键，同一幂等键重放返回原资源并标记重放，不同幂等键命中同一外部编号视为更新；登录名创建后不可改，必填属性不能被删除操作清空，未知操作符和重复多值一律拒绝；PATCH 沿用 If-Match 语义的版本号，落后即冲突，成功后版本加一；租户由构造参数固定，请求体里的租户字段必须一致；列表默认只返回活跃资源，起始序号从 1 开始，每页条数超过上限按上限截断，非法分页抛 ValueError；停用是软删除且重复调用幂等，恢复供应复用原主键并把版本加一；响应和查询结果不能含密码，也不允许调用方改坏内部状态。15 条测试现在全红，断言不许动。

## 运行方式
```bash
python -m pytest tests -q
```
