# GSB Bugfix Task
## 题面
合作伙伴报表接口开放后，账单显示有人用一条查询把网关的解析量放大了几千倍：字段层层嵌套、同一字段挂满别名、片段互相引用成环、分页参数填到上限。旧实现按字符串里冒号的个数估算深度，片段展开不计成本，别名不去重，内省字段照样能查，订阅和变更也没有和查询分开，每个伙伴的调用配额还是所有接口共用一个计数器。partner_graphql_budget.py 中的 PartnerQueryBudget 在执行前算清代价。入口接收已解析好的操作文档，含操作类型、选择集和片段表；只允许查询，变更与订阅直接拒绝；字段名以下划线打头的按内省处理；深度按选择集逐层累计，片段展开后的层级也算进去；代价按每字段一分、分页参数对子选择乘法放大计算，分页值须是规定范围内的整数，超出上限单独报错；别名不得指向不同字段，别名总数有上限；片段必须存在，展开时检测循环，成环立即报错；总代价超过上限拒绝；通过后按伙伴扣减配额，配额按时间窗口重置，余额不足报专用错误；测量结果给出深度、代价、别名数、字段数；计数视图给出扣减与拒绝两项，是副本。片段展开要防指数膨胀，同一片段在同一层重复展开只计一次并标记。参数出现负数和浮点数都拒绝。这组题共十五条断言，现在都没有通过。

