# GSB Bugfix Task
## 题面
统一日志平台上线后，值班同学在检索界面看到凭空多出的错误级别记录，点开发现是用户在昵称里塞了回车换行，把一行拆成两行；还有人用制表符和退格把后面的字段盖住，用零宽字符和行分隔符伪造时间戳；带引号的昵称让键值对错位，反斜杠结尾把下一行吞掉；字段名里出现空格和等号，解析器把值当成了新键；调用方把整个异常对象塞进附加字段，浮点数和空值直接渲染成字符串；单条记录字段过多、单个值过长，把采集端撑爆；保留字段被业务字段覆盖，级别大小写混用也照收；采集端按空格切键值对，值里的等号把后半个字段推成新键；事件名超长被截断后与另一个事件重名；布尔值被写成大写，下游当成字符串；多个线程共用同一块缓冲区，行与行互相覆盖。structured_log_guard.py 的 StructuredLogGuard 要统一渲染：构造参数给出单值长度上限、字段数量上限与允许的级别集合；级别必须命中集合且为大写，事件名只允许小写字母、数字、点、下划线与连字符；附加字段名同样限制字符集，且不得占用时间、级别、事件与消息四个保留名；字段值只接受字符串、整数与布尔，字符串不得含空字节、回车、换行、制表符、退格、转义字符以及行分隔符类不可见字符，超长直接拒绝；渲染时按时间、级别、事件、其余字段名排序，字符串值一律加双引号并转义引号与反斜杠，整数与布尔不加引号；输出单行文本，不得出现真实换行；级别集合先去重再比较；时间必须是非负整数；字段名按字典序排序；拒绝计数要覆盖级别、事件名、字段名与字段值四类；渲染失败时异常信息不得带原始值；统计接口给出渲染与拒绝次数，返回副本，并发下计数准确。

## 运行方式
```bash
python -m pytest tests -q
```
