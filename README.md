# GSB Bugfix Task
## 题面
跨区域备份恢复演练出了事故：开发集群的备份被恢复到生产租户，加密上下文只比了备份编号；上下文少一个必填键、或者多带一个自定义键，封装接口都放行；值前后带空格也能通过；值的大小写被统一后再比较，两个不同租户被当成同一个；备份编号和上下文里的编号不一致没人发现；块列表为空也生成清单；块数据不是字符串也照算摘要；清单里的块编号为空也通过；清单摘要被替换后，代码重新计算的是被篡改后的上下文；块清单里同一编号出现两次，恢复时后一块覆盖前一块；块顺序被调换，恢复出来的数据错位；缺失的块、额外的块、哈希不符的块分别被静默跳过；打开后返回的顺序按调用方给的顺序，不按清单顺序；打开时没有核对备份编号与期望上下文的关系；清单签名校验失败继续执行；签名回调抛异常直接冒泡；过期清单照样恢复；同一清单被并发打开，快照计数丢了一半；快照保留块明文。backup_encryption_context.py 的 BackupContextBinder 要绑定恢复上下文：封装时校验必填键集合完全相等、值去空白后非空、备份编号一致、块编号唯一且非空、块列表非空且块数据为字符串；清单摘要用规范化后的上下文计算，不做大小写归一；打开时先验签名再验摘要，然后逐字比对期望上下文，租户不同单独报错，备份编号也要对上；清单有有效期；块必须全部到齐、不得多余、摘要匹配，且每块的附加摘要要绑定上下文、块编号与序号，顺序不能换；返回顺序以清单为准；任一步失败都不能返回部分结果；快照计数加锁且为副本。仓库里 15 条用例现在全挂。

## 运行方式
```bash
python -m pytest tests -q
```
