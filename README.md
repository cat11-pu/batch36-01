# GSB Bugfix Task
## 题面
单页应用改用持有证明来换令牌，上线后渗透测试指出了不少破绽。证明头里的类型写成普通 JWT 也收；算法允许 none；密钥对象里带上私钥参数仍然接受；证明中的密钥指纹和刷新记录里的绑定值不比对；请求方法小写也通过；请求地址带了查询串或片段还能匹配；签发时间停在十分钟前照样有效；证明编号重复提交没有拦截；编号只判空不判重，窗口内可以反复出现；服务端下发的随机数过期后还能用，传空串则被当作免检；刷新时换一把密钥也能续期；刷新凭据可以换主体续期，审计里出现两个身份共用一条记录；签发返回的指纹和证明里的密钥对不上也照发；令牌记录不写过期时间，重启后全部变成永久有效；旧刷新凭据用过一次后再次提交，居然又发了一套新令牌；验证失败的请求仍然把声明回给调用方；未知应用直接拿到令牌；令牌类型返回成普通持有者；刷新凭据没有和应用、主体绑定。dpop_binding.py 的 DpopBoundTokenService 负责下发挑战、签发和刷新：挑战随机数要有足够熵并记录过期时刻；证明必须校验类型、允许的算法集合、密钥不含私钥材料、方法大写精确、请求地址逐字匹配、签发时刻落在允许偏差内、证明编号在窗口内一次性、随机数属于本服务且未过期；签发时把密钥指纹写进令牌记录并返回指纹；刷新时证明指纹必须与记录一致，刷新凭据只能使用一次，轮换后旧值立即失效，新令牌继续绑定同一密钥，应用与主体保持不变。需要十五条测试全部通过，且不改动断言。

## 运行方式
```bash
python -m pytest tests -q
```
