# GSB Bugfix Task
## 题面
分析产品的多租户查询编译器前阵子把两家客户的数据混进了一张报表：客户端在筛选条件里自己塞租户条件，把自动注入的那条覆盖掉；联表时只写了业务键，没带租户键，结果把另一家同名用户的行也拼了进来；公共维表被误当成租户表拒绝，修复后又反过来漏加租户谓词；缓存键没带租户，甲家的结果直接返回给乙家；子查询和并集完全绕过作用域。请重写 tenant_scope_planner.py 里的 TenantScopePlanner：初始化接收表字典和公共表集合，租户表声明租户列，公共维表必须显式登记。规划方法接收租户标识和查询描述，查询里有选择列、主表、联表和筛选条件，返回语句、参数、缓存键、涉及表和是否跨租户。租户表必须自动追加“表名.租户列 = 占位符”形式的谓词，主表和每张联表的租户值按出现顺序排在最前，原有筛选条件按原顺序跟在后面；客户端自带租户列条件、并集、未知表、空租户都拒绝；联表两边都是租户表时自动补租户等值条件；公共维表不补租户谓词，但没登记的公共表照样拒绝。缓存键里必须带租户标识，同租户同查询稳定，跨租户必须不同。管理员跨租户查询必须带以事故单号开头的凭证，否则拒绝；带凭证时结果标记为跨租户，并且不再注入租户谓词。表和列名只允许字母、数字、下划线，出现空格、分号、注释符直接拒绝；查询描述必须是字典，选择列不能为空，主表必须是字符串，联表和筛选必须是列表。仓库里十五个用例目前全红，测试保持原样；另外会用多线程同时规划不同租户，参数不能串。联表条件里的表名必须在本次查询的主表或联表里出现过，引用未参与的表直接拒绝；公共维表如果作为主表，不强行加谓词，但仍参与缓存键；规划结果不能引用调用方后续修改的查询对象。

## 运行方式

```bash
python -m pytest tests -q
```
