# GSB Bugfix Task
## 题面
对象存储切到信封加密后，安全审计复现了几条越权路径：密钥已停用，加密接口还在签发新数据密钥；密钥销毁后，旧密文仍能解开；密钥的生效时间写在未来也能用；到达退役时刻后还在接受新加密；解密时不比对加密上下文，换个租户标签也能解；上下文的键不是字符串也照存；上下文摘要被改动，代码只看明文上下文；包装后的数据密钥损坏，解包返回空值被当成成功；密文完整性校验失败，异常被吞掉；明文为空也生成数据密钥；解密失败也扣减了数据密钥可用次数；同一密文被两路并发解密，两个调用方都读到最后一次计数；换绑到已停用的密钥也成功；换绑失败时旧密文被改坏；轮换包装密钥时把原文重新加密了一遍，审计链断裂；快照里的计数被调用方清零后内部也归零。kms_envelope_ledger.py 里的 EnvelopeCipher 负责这套流程：加密前校验密钥存在、状态可用、已到生效时刻且未过退役时刻；上下文必须是字符串键值对，键集合固定且不能为空，明文必须是非空字符串；数据密钥只用于一次封装，包装令牌与密文分开存放；解密先校验上下文摘要与上下文本身，再解包并做完整性校验，任一步失败都不能消耗次数，计数扣减必须原子；支持把旧密文换绑到可用的新密钥而不触碰密文主体，换绑失败不得改动原对象；销毁后的密钥不再参与任何操作；密钥状态与计数在同一把锁里更新；快照只保留密钥状态、计数和摘要，且为深拷贝。十五条用例目前全部失败。

```bash
python -m pytest tests -q
```
