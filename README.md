# GSB Bugfix Task
## 题面
电视端接入设备码登录后，客服收到一堆投诉。用户码念错一位也能通过，因为服务端只比较了前缀；轮询没有节流，客户端一秒打十几次，授权服务被打满；设备码在签发十分钟后仍然能换令牌，过期时间形同虚设；同一个用户码被两个账号先后确认，后一次覆盖了前一次；令牌发出去之后原设备码还能再换一次；大小写不同的用户码被当成两个码；未知设备码直接返回内部异常，泄露了存储结构；授权范围没有去重，重复申请会放大权限；设备码没有和客户端绑定，另一台设备拿去也能兑换；确认人主体为空字符串也写进了记录。oauth_device_flow.py 的 DeviceAuthorization 要实现设备授权全流程：start 校验客户端与授权范围，授权范围要去重并逐项比对白名单，签发高熵设备码和形如四段连字符的短用户码，并记录过期时间与轮询间隔；approve 只接受未过期的用户码，大小写不敏感，但同一码只能确认一次，重复确认要拒绝；poll 在用户未确认时返回等待状态，请求早于允许时刻返回降速状态并把间隔加长，冷却结束后恢复普通轮询；确认后只兑换一次令牌，重复兑换按无效授权拒绝；流程过期后再轮询或确认都要报过期；未知设备码不能泄露任何状态；设备码必须绑定签发时的客户端，跨客户端兑换按无效授权处理；空主体不能确认。所有异常都通过带错误码的自定义异常抛出，调用方按错误码分支，不能靠字符串匹配。15 条测试必须全部通过，且不能修改测试里的断言。

## 运行方式
```bash
python -m pytest tests -q
```
