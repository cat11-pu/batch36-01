# GSB Bugfix Task
## 题面
数据开放平台的属性策略最近连续误判。财务口径的报表本该只给财务和审计，条件里少一个属性却被当成满足；外包标记一加上，发薪报表的拒绝规则反而不触发；同一份资源在办公网段外也能读；规则编号撞车后后写的覆盖前写的；数值比较拿到字符串直接算错。请重写模块 attribute_gate 中的 AttributeGate：构造时传入一组规则，一条规则包含编号、判定效果、操作动作、目标资源和条件树。动作和资源允许星号通配，资源名就是类型加名字；条件树用全部满足、任一满足、全部不满足三种组合，叶子写成属性、比较符和目标值，属性路径按点号从请求的主体、资源、上下文里逐层取。比较符覆盖等于、不等于、落在集合内、落在集合外、小于、小于等于、大于、大于等于、存在和网段包含；缺少属性时普通叶子为假，存在性判断才看有无；数值比较遇到字符串或布尔要报错；未知比较符、重复编号、缺失或非法效果、请求缺动作，都会在构造或判定阶段抛出专用异常并带上错误码。命中的规则全部收集，拒绝压过允许，没有命中给出 no_match，允许时带上义务项。命中列表按规则原顺序，义务项给副本。策略在加载阶段只做静态检查，不执行条件；判定时遇到不认识的属性路径按缺失处理；全部满足里任意一个叶子为假整条不命中，任一满足至少一个为真，全部不满足要求每个都为假；资源匹配只对类型和名字两段展开星号，不允许星号跨过冒号；义务项只从最终允许的规则里收集，拒绝规则的责任不执行；结果对象每次新建。随包的十五个用例眼下没有一个能过，测试那部分保持原样；同一请求反复判定必须完全一致。

