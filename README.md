# GSB Bugfix Task
## 题面
集群权限排查器接手后，开发同学反馈三件事对不上：同名角色绑定只在命名空间内生效，但排查结果说全局可读；集群角色通过角色绑定绑定后，跨命名空间也能命中；服务账号的命名空间被忽略，别队的机器人账号拿到了本队权限。请重写模块 k8s_rbac_resolver 中的 KubeRBACResolver：构造时传入命名空间角色表、集群角色表、角色绑定表和集群角色绑定表，命名空间角色用“命名空间/名字”做键，集群角色用名字做键。角色绑定只在其命名空间内生效，引用命名空间角色时按同空间查找，引用集群角色时只借用规则但作用域仍限于该命名空间；集群角色绑定全局生效且只能引用集群角色。规则匹配接口组、资源、动词、资源名和非资源路径，允许星号通配；资源名里的斜杠表示子资源，基础资源规则不能顺手放行子资源；资源名清单非空时名字必须命中；非资源路径只能通过集群角色绑定生效。聚合集群角色按标签选择器合并带标签集群角色的规则，标签不匹配就不合并。主体支持用户、用户组和服务账号，用户组从请求的组列表匹配，服务账号的名字和命名空间两个都要对上。权限查询返回布尔，解释查询额外给出命中的绑定名字列表；缺失的角色引用、集群角色绑定引用命名空间角色、角色绑定缺命名空间都要在构造阶段报错并带错误码。随包十五个用例一条都过不了，测试部分保持原样；多路并发查询同一主体时，答案必须相同。主体字典必须带类型和名字，用户组可以为空，服务账号必须写清所属命名空间；解释结果的绑定名字去重后按字典序排列，拒绝时给空列表；角色和集群角色的规则列表允许为空，空规则不授予任何权限；沿用同一绑定里多个主体逐一匹配；接口组匹配要求请求组在列表里；绑定名字全局唯一，重复名字直接报错。

## 运行方式
```bash
python -m pytest tests -q
```
