# GSB Bugfix Task
## 题面
身份提供方这季度轮换签名证书，元数据端点同时挂着旧密钥和新密钥。值班同学发现，旧密钥已经过了下线时间，仍有一批服务提供方能从缓存里拉到旧元数据并完成单点登录；有租户把 EntityID 改成自家域名，校验层只比较了主机后缀，照样放行；另一份元数据的 validUntil 已经过去三天，缓存却继续信任；更麻烦的是，签名引用指向文档内部节点而不是整个实体描述，XML 里再塞一张自签证书也能通过；还有运维把加密用途的密钥填进签名配置，系统没有区分用途；同一份元数据声明了两张签名证书，代码只取了第一张；缓存时长字段被完全忽略，下游一直拿着过期文档；单点登录地址指向外部域名，也没有和实体标识做归属校验。saml_metadata.py 里的 MetadataTrustStore 负责加载和校验身份提供方元数据：EntityID 必须与预期值逐字相等，前后空白字符要先裁剪，缺字段直接拒绝；签名密钥必须存在、用途为签名，且当前时刻落在它的生效窗口内；文档里声明的签名证书指纹要和信任锚一致；签名引用必须覆盖整个实体描述，摘要必须是六十四位十六进制；validUntil 既不能早于当前时间，也不能超过配置的最长缓存期。轮换重叠期内新旧锚同时可用，旧锚退役后只认新锚，trusted_keys 要按当前时刻返回可用密钥，且不能把用途不符的加密密钥混进来。构造时重复的密钥标识要拒绝，信任锚缺指纹或缺有效期同样拒绝，validate 返回的快照不能被调用方改坏内部状态。要求 15 条用例全部转绿，不能改测试。

## 运行方式
```bash
python -m pytest tests -q
```
