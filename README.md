# GSB Bugfix Task
## 题面
合作方接进来以后，联合登录的断言开始被安全团队反复挑刺。签名挂在外层响应上，里面塞一张完全没签名的断言也能登录；签名节点在响应外层、引用却指向断言，也被当成合法；文档里两个元素用同一个标识，验签时取到的是另一个；引用指向不存在的标识，代码却回退到第一条断言；一份文档里挂了两处签名，只取第一处；变换列表里混进注释处理和两条规范化，摘要照样算得过；摘要长度不足也接受；签发方不在白名单仍然放行；受众字段用的是包含匹配，别的服务方的断言能复用；接收地址只比较主机；断言过期时间已经过去半小时还被信任；截止时刻缺字段时按零处理，等于永久过期却仍放行；发起时刻写到了未来也没有人管；请求编号和本次编号对不上；主题为空字符串直接入库，空格也被当成一个合法主体；断言数组为空时直接返回成功；响应编号和断言编号相同也能通过；多条断言同时出现时只校验第一条。saml_wrapping_guard.py 的 AssertionWrappingGuard 按结构化文档验收：断言列表必须恰好一条，所有标识必须非空且全局唯一，响应编号不能与断言编号冲突；签名必须是断言的直接子节点，引用标识必须等于该断言自身编号，变换只允许封装签名加独占规范化且顺序固定，摘要为六十四位十六进制；签发方、受众、接收地址三者精确匹配；当前时间不能超过截止时刻加偏差，发起时刻不能过分超前；请求编号必须与本次一致，主体不得为空。测试里的十五条断言眼下全是失败，文件不许动。
