# GSB Bugfix Task
## 题面
账号申诉改成双人复核，黑产还是找到了口子。同一份证件材料换个账号再交，系统照单全收，一次取证被反复利用；申请人自己就能给自己批；同一个复核人点两次算两票；票数不够也生成了重置凭据；凭据发出去长期有效，案件关了还能用；凭据兑换过一次还能再兑；申诉过了七天不失效，旧案一直挂着；已拒绝的案件还能继续审批；案件号不存在时返回空对象，调用方当成成功；账号标识是空串也建了案；重置结果把内部案件对象交出去，调用方一改状态就变成完成；两个线程同时兑同一凭据，两路都拿到重置结果。recovery_case_binder.py 的 RecoveryCaseBinder 管住申诉：建案时账号、申请人、材料摘要必填，同一材料只能绑一个账号；申请人不得复核，同一复核人只计一票，票数达标才发一次性重置凭据；凭据只存摘要并绑定案件，换案件不能兑，兑一次即废；案件有期限，过期、已拒绝、未达票数都不能兑；未知案件、重复兑换、材料复用各报各的错误码；申请人、复核人和账号标识都去空白后比对，大小写差异按同一人处理；材料摘要为空或纯空白直接拒绝；复核人列表里不能出现申请人本人；案件号由服务端生成，同一账号重复建案复用未结案的那件；拒绝案件要记录处理人，已完成的案件不能再审批；案件完成后所有凭据立即失效；申请人、复核人与账号的比对要在入库前完成；案件记录只存材料摘要不存原件；同一案件重复拒绝按幂等处理；兑换成功后案件与凭据同时落状态；快照是副本，且不出现凭据原文。十五条用例现在全红。

