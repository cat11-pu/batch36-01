# GSB Bugfix Task
## 题面
协作编辑器嵌入第三方预览组件后，父页面开始收到伪造的配置消息：攻击页面把窗口引用指过来，发一条尺寸变更就把画布改成零；来源为空字面量也照收；目标窗口写成星号，子页面把令牌发给了任意父窗口；消息来源窗口没有与登记过的嵌入框比对；消息体不是对象时直接取属性导致异常；深层对象里出现三个特殊键名，合并后污染了共享对象；超长字符串把内存打满；消息类别不在约定集合里也执行；通道号与协商值不一致；一次性串缺失或重复使用；序号跳跃后仍按顺序处理。postmessage_receiver.py 的 PostMessageReceiver 负责接收端校验：初始化时传入受信来源、受信窗口、允许类别、单条字节上限、复用窗口和最大序号间隔；接收入口要求来源存在、不能是空字面量、不能带路径或末尾斜杠，并与集合逐字匹配；目标窗口不得为星号；来源窗口必须在登记名单内；消息体必须是字典，编码成文本后不得超过配额；类别必须命中允许集合；通道号必须与该窗口协商值一致；一次性串仅接纳由字母数字与连字符下划线组成、长度合规的值，复用区间内重复判为重放；序号必须是正整数，相对上一序号只能递增且间隔受限，倒退或重复单独报错；消息体递归检查，出现原型污染相关键名立即判非法；返回类别、序号与窗口标识；计数视图汇总接收与异常数量，结果不可反向污染内部状态。事件里的多余顶层字段允许存在但不得进入返回值；同一窗口的通道号变更必须重新协商；一次性串与来源、通道绑定，换一个窗口复用同一串也算重放；序号上限要防溢出，超过三十二位正整数直接驳回；消息体的键必须是字符串，数组长度与嵌套深度都要设配额；字符串值里的控制码要驳回；失败返回不得回显原始消息体；计数视图另按接收、重放与格式错误分组。仓库里的十五条用例目前均未通过。
