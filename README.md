# GSB Bugfix Task
## 题面
短信通道被刷之后，财务发现单日账单翻了几十倍。同一个号码一分钟内连发二十条，服务端没有任何节流；号码带不带加号、带不带分隔符被当成不同用户，换个写法就能绕过限额；同一出口 IP 下批量请求也没有上限；全局每日预算没人统计，凌晨被打穿；冷却时间配置成负数，等于永不冷却；封禁号段只在前端拦截，后端照发；号码里混入字母和空格也被接受；限流窗口用固定时间桶，整点前后可以打双份；被限流的请求不返回重试秒数，客户端只能盲猜；计数表从不清理，跑一周内存翻倍；两个请求同时到达，各自读到旧计数，都放行；快照被调用方改写后，限额记录被清空；系统时钟被回拨，旧计数反而变成未来时间。sms_otp_throttle.py 的 SmsOtpThrottle 要实现发送节流：号码规范化为带加号的纯数字 E.164 形式，容忍空格、括号和连字符，非法号码直接拒绝；按号码、按 IP、全局三个维度做滑动窗口，另设冷却与每日上限；命中任一限制抛出带错误码与重试秒数的异常，重试秒数按最早一条记录到期时间计算，必须是正整数；被封禁号段一律拒绝；窗口外的记录要清理；同一个号码的不同写法必须落到同一个桶里，不能靠加空格绕过；按 IP 的限制要把 IPv4 与 IPv6 分开统计；全局上限被触发时也要给出可读的重试秒数；快照里只放计数和时间，不放号码原文；时钟回拨明确报错；并发下同一号码只放行一个；快照深拷贝，调用方清空后不能影响限额。仓库自带的十五条用例全红，测试文件不可修改。

## 运行方式
```bash
python -m pytest tests -q
```
