# GSB Bugfix Task
## 题面
入口层升级后，上游偶尔收到从未发送过的请求，访问日志里也出现同一连接上两个报文被粘在一起。安全同学复现出两类打法：前端按声明长度截断，后端按分块编码读取，剩余字节就成了队列里的下一个报文；两个长度字段同时出现时程序取了靠前那个，重复的分块声明被简单拼接，值里带正负号、逗号列表或首尾空白都被放行；编码名写成大小写混合、附带参数也能通过；旧版协议携带分块声明无人拦截；续行折写被当成普通字段；字段名与冒号之间夹空格仍可解析；分块体末尾少一个回车换行也被接受；新版协议里出现连接管理类字段同样放行。http_frame_arbiter.py 的 HttpFrameArbiter 要在转发前锁定报文边界：字段名转小写并校验 token，拒绝折行、冒号前空白和值中的控制码；声明长度只接受纯十进制数字，重复出现或与分块声明并存时直接判非法；分块声明只认单个分块编码，比较前统一字母大小写并去掉首尾空白，列表、参数和重复字段都不接受，旧版协议禁止使用；没有任何长度信息按空体处理；声明长度必须等于实际字节数；分块体按十六进制块长解析，以零块加空尾结束；新版协议下连接管理字段一律驳回；体量越界单独报错；结果返回规范化模式与长度，统计接口在并发下计数准确且为隔离副本。字段总数与单行长度都要设配额；声明长度带前导零按十进制解释但仍只允许数字；分块扩展只接受分号后的 token，块长超过剩余字节立即失败；最后一个零块之后除可选尾部字段外不得再有内容；尾部字段也要按普通字段校验，且不得夹带边界相关信息；连接建立与协议升级请求单独处理；同一连接上的第二个报文必须重新走完整校验；失败时不得回显原始字段值，记录里只留错误码与位置。这组用例现在十五条全红。

## 运行方式
```bash
python -m pytest tests -q
```
