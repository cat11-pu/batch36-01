# GSB Bugfix Task
## 题面
硬件加密机做密钥仪式时，审计员指出流程可以被绕过：两个持有人的份额编号写成同一个，系统只按份额计数，阈值被一个人凑满；份额编号还可以由持有人自选；持有人名单里有重复名字也建了仪式；同一持有人把名字换个大小写再交一次，被算成新份额；同一时间开了两场仪式，份额交叉提交；仪式过了有效期还能继续收份额；份额提交后没有记录谁交了什么，事后无法追溯；达到阈值后继续提交也不报错；密封时份额不够仍返回密钥句柄；密封返回的证人列表里混进没交份额的人；份额提交顺序影响最终证人列表；已经密封的仪式还能中止，中止后又能重新密封；中止理由为空也接受；重复中止被当成成功；中止事件没有写进日志；未知仪式查询审计直接抛键错误；仪式编号带空白时没有规范化；并发开启两场仪式都成功；快照能看到份额原文。hsm_key_ceremony.py 的 HsmKeyCeremony 要实现 M-of-N 仪式：构造时校验阈值不超过总份额且至少为二；开启仪式要求编号去空白后唯一、持有人数量等于总份额且去空白后互不重复，同时只能有一场进行中，开启要加锁；份额编号由服务端分配，提交时核对持有人、分配的编号、重复提交与重复份额，并受有效期约束；收满阈值即封口，多余提交报错；密封要求份额达标且只执行一次，返回密钥句柄与只含实际提交者的证人列表，证人顺序稳定，绝不回传份额；中止要理由且不可逆，也要留痕；审计日志按时间记录事件，查询未知仪式返回专用错误；密封后审计不得为空；快照为副本。十五条断言眼下全红。
