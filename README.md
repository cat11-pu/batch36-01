# GSB Bugfix Task
## 题面
身份提供方把 POST 绑定换成工件解析后，登录偶发失败，重试又好了。类型码写成 0x0003 的工件也被受理；长度不对、Base64 填充缺失的字符串直接进解码器，异常冒到网关；同一个工件解析两次，第二次又签发了一张断言；工件过了两分钟仍然有效，过期时间形同虚设；来源标识被改掉，服务端只看了消息句柄；端点索引写成另一个值也能解析；发给别的 SP 的工件在本 SP 也能换出断言；解析过的句柄没有从表里摘掉，内存一路涨；未知句柄返回空而不是明确错误；签发时断言引用为空也照样出工件；同一工件被两个线程同时解析，两张断言都发了出去；快照把内部句柄原样暴露，调用方清空后内部表也空了。saml_artifact_vault.py 的 ArtifactVault 要实现 SAML 2.0 工件签发与解析：工件为 44 字节、类型固定 0x0004，含端点索引、来源标识与消息句柄；签发要求 SP 标识与断言引用非空；解析要校验编码、长度、类型、来源标识、端点索引与 SP 归属，并在 TTL 内一次性消费；签发时端点索引必须是非负整数，负数直接拒绝；工件里的消息句柄由服务端随机生成，不能由断言引用推导出来；同一断言引用重复签发要得到不同工件；解析前先去掉工件首尾空白，中间夹空格按编码错误处理；TTL 从签发时刻算起而不是解析时刻，过期判断用调用方传入的当前时刻；解析失败不能把待处理记录删掉，成功才摘除；未知、过期、已用分别给出不同错误码；快照深拷贝，且不能带出仍然可用的工件。仓库十五条断言目前全红，测试文件不可改。

## 运行方式
```bash
python -m pytest tests -q
```
