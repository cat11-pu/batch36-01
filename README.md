# GSB Bugfix Task
## 题面
通行密钥注册接进三家硬件厂商后，认证器数据开始互相串。运营为了排查问题，把一台开发机的自签证书加进信任列表，结果任意厂商的打包声明都能通过；挑战值发出去十分钟仍能拿来注册，同一个响应重放两次还会生成两条凭证；有请求把来源域名写成测试站点，依赖方标识的哈希也没对上，服务端只检查长度就放行；无证明格式默认被当成合法声明，声明体里没有签名也照样入库；硬件厂商证书链的根节点不在锚里，也被当成可信；同一凭证编号被两个账号重复注册，旧记录直接被覆盖；用户验证标志始终为假，策略却要求必须验证；认证器计数器倒退没有触发任何告警；被列入黑名单的认证器型号仍然可以完成注册。webauthn_attestation.py 的 AttestationVerifier 负责签发一次性挑战和验收注册响应：挑战绑定用户、过期即废、成功消费后不能复用；来源域名必须精确命中白名单，依赖方标识的哈希要用 SHA-256 比对；证明格式只支持打包、硬件厂商和空证明三种，签名算法必须属于允许集合，空证明需要显式开关；打包格式必须带算法与签名，证书链根的指纹要能在信任锚里找到且锚未过期；签名校验回调返回假就拒绝；凭证编号不能重复注册；认证器计数器必须单调不减，倒退视为克隆信号。挑战签发要限制每个用户的未完成数量，重复签发时旧挑战立即作废。注册成功后 credentials 返回凭证快照，外部改动不能污染内部状态。仓库里的 15 条断言眼下全红，测试文件不许动。

## 运行方式
```bash
python -m pytest tests -q
```
