# GSB Bugfix Task
## 题面
公司把内部工单门户的登录迁到云端身份平台，审计报告列出一长串问题。回调白名单原先只看域名结尾，攻击者注册形似子域就能把凭据截走；同一张兑换凭据被重放后又能开出一个新会话；代码挑战的校验值放在请求里，服务端却没有和开局时保存的那份对照；身份令牌里的随机串与本次发起不匹配也照样放行；受众写成数组时只检查第一项，别的应用的令牌混进来；授权方字段缺失也被视为合规；签发域名填成演练环境仍能通过；认证时刻离当前太久，本该要求重新认证，却直接沿用旧会话；签名密钥编号不在有效集合里，验签步骤被整段跳过；令牌有效期没有和当前时刻比较；会话表按会话编号直接覆盖，两个工号撞号就互相踢下线；兑换时把登记过的另一个回调地址传进来也能成功；认证强度声明只是单因素却被当作满足多因素；会话查询返回的字典被调用方改写，下一次读取拿到脏数据。oidc_code_exchange.py 里的 AuthorizationCodeBroker 需要实现开局与兑换两段：登记过的应用和回调地址必须逐字相等；兑换凭据要绑定应用、回调地址且只能消费一次，超时立即作废；代码挑战必须用开局时下发的那份校验值做逐字比对；身份令牌的签发方、受众和授权方要与本地配置一致，多受众时必须带授权方且等于本应用；随机串必须对应本次开局；认证时刻超过上限按需要重新认证处理；密钥编号必须命中当前启用的公钥；会话按会话编号归并，重复建立要拒绝。错误用带编号的自定义异常抛出。仓库里十五条断言目前全红，测试保持原样。

## 运行方式
```bash
python -m pytest tests -q
```
