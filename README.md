# GSB Bugfix Task
## 题面
运维把堡垒机改成 SSH 用户证书后，CA 轮换当天出了事故。旧 CA 已经下线，证书却还在被接受；新 CA 还没到生效时间，签出来的证书已经能登录；有张主机证书被当成用户证书放行；允许主体列表里混进一个未授权账号也没人拦；关键选项写了未知字段，服务端直接忽略；来源地址限制只打印日志不生效；强制命令没有回传给审计系统；证书生效截止时间早于生效开始时间也能通过；通配主体被默认放行；签名校验失败时函数只记录警告继续返回成功；两张 CA 用了同一个标识，加载时没有报错；强制命令写成空字符串也能通过；客户端地址传进来是非法文本，解析异常直接冒泡；证书主体列表里带空字符串，被当成合法主体。ssh_cert_authority.py 的 SshUserCertAuthority 要按信任 CA 列表验收用户证书：证书类型必须是用户证书，CA 标识要存在且当前时刻落在它的生效窗口内，轮换重叠期两把 CA 都可用，退役后旧 CA 立即失效；签名回调必须返回真；主体列表非空且逐个落在允许集合里，默认不接受通配；生效开始与截止时间要包住当前时间；关键选项只认识强制命令、来源地址和需要用户验证三项，未知项拒绝；来源地址用 CIDR 校验客户端地址，格式错误或不在网段内都拒绝，强制命令必须是非空字符串并原样返回给调用方。信任 CA 列表加载时重复标识要拒绝，缺公钥或有效期倒挂也要拒绝；允许主体集合不能为空。仓库自带 15 条断言全部失败，测试文件不得改动，也不能硬编码测试输入。

## 运行方式
```bash
python -m pytest tests -q
```
