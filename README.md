# GSB Bugfix Task
## 题面
后量子迁移试点把混合密钥封装接进握手后，互通测试暴露一串问题：客户端同时报经典与混合套件，服务端按自己顺序选了经典套件，降级没有任何提示；套件列表里有重复项、未知项，协商照常进行；套件名大小写不同被当成两个不同的套件；协商编号为空也建会话；客户端公钥长度明显不对，封装函数直接越界；公钥不是字节串时直接做字符串拼接；握手记录为空或者两端不一致，密钥确认仍然通过；封装返回的密文长度异常、共享密钥长度不足，都没有校验；封装函数抛异常时原样冒到调用方；同一个协商编号被响应两次，生成两套会话；响应阶段没有核对协商里的套件与当前策略是否仍然允许；确认标签错了也建立会话；会话过期后还能确认；同一会话被两个线程同时确认，两边都成功；确认成功后会话仍可再次响应；未确认会话没有数量上限；快照把共享密钥原样带出，调用方清空后内部会话也空了。pq_kem_session.py 的 HybridKemBroker 要实现混合 KEM 协商：按客户端偏好选择双方都支持的套件，强制混合模式下拒绝纯经典套件；套件不得重复，未知套件直接拒绝，协商编号非空；响应阶段校验公钥为字节串且长度符合套件、握手记录非空、密文长度与共享密钥长度正确，封装异常转成专用错误码；确认标签由共享密钥对握手记录和会话编号计算，必须匹配；每个协商只能响应一次，每个会话只能确认一次且有有效期；待确认会话数量设上限；快照不含任何密钥材料且为副本。十五个用例现在全红，测试文件不能动。

## 运行方式
```bash
python -m pytest tests -q
```
