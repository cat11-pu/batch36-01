# GSB Bugfix Task
## 题面
移动应用把授权参数拼进跳转链接，长度一超就被网关截断，团队改成先推送再跳转，结果实现漏洞不少。登记检查只在推送时做了一次，领取阶段换个应用也能把参数拿走；响应类型不在白名单照样签发请求地址；权限范围混入未审批项也不拦；公开类型的应用不带挑战值依旧受理，挑战方法写成明文也不拒绝；参数里再嵌套一层请求对象或请求地址，服务端当没看见；参数容器不是字典时直接抛类型错误，堆栈漏进网关日志；路径里的应用标识与参数中的副本不一致也接受；回调地址只比前缀；状态串缺失时悄悄补空；权限范围用逗号分隔，整串被当成一项；请求地址的有效期由调用方随意填写，填一整天也放行；同一个请求地址能反复领取；过期之后仍可取；地址前缀大小写混写也认；未知地址直接抛内部异常，暴露存储细节；推送成功的响应没有到期时刻，调用方只能猜；领取到的结构漂移，权限范围有时是字符串有时是列表。par_registry.py 的 PushedRequestRegistry 要实现推送与领取：推送阶段核对应用、响应类型、权限白名单、回调地址精确相等、状态串非空、公开应用强制 S256 挑战，并拒绝嵌套的请求对象，路径应用标识必须与参数副本一致；有效期取调用方请求与服务端上限的较小值；请求地址要一次性、高熵、固定前缀；领取阶段核对归属应用、是否过期与是否存在，返回规范化副本；权限范围按空白切分、去空、去重后转列表，返回字典不能被调用方改坏后续读取。错误通过带编号异常表达。十五条用例等待转绿，断言不许改。
