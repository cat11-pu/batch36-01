# GSB Bugfix Task
## 题面
反向代理前的规则引擎最近连续被绕过：攻击者把关键字写成全角字母，把百分号编码套两层，在 union 和 select 之间插注释，用加号代替空格，再用零宽字符把特征切开，原有规则只看原始请求体，全部失效。维护同学又发现几个反向问题：正常的中文被当成乱码拒绝，超长参数解码后把内存涨满，未闭合的注释让整段内容直接跳过检测，孤立的代理项把日志写坏；同一参数在两层编码之间混用大小写百分号，解码层数忽多忽少；全角空格与半角空格混排后规则再次漏检；注释被替换后前后关键字粘成一个新词；规范串长度在解码后膨胀数倍，下游缓冲区告急。waf_payload_canonicalizer.py 的 WafPayloadCanonicalizer 要输出供规则引擎使用的规范形式：构造参数给出解码层数上限、输入长度上限与模式，模式只认 text、query、json 三种。输入必须是字符串；查询模式下先把加号换成空格，再逐层做百分号解码，每成功解开一层计数加一，达到层数上限后若仍存在合法的百分号三元组就单独报错；解码结果出现空字节立即拒绝。随后按模式处理转义，json 模式解析反斜杠转义并拒绝孤立代理项与非法转义。再做兼容分解，把全角字母数字折叠成半角，遇到零宽、双向控制等不可见字符直接拒绝。块注释整体替换为一个空格，未闭合的块注释与只有起始标记的输入都判非法。连续空白压成一个空格并去掉首尾。空串返回空规范串且层数记零；百分号后跟非十六进制字符按普通文本保留，不参与层数；模式取值非法时在构造阶段报错。输出包含规范串、实际解码层数与处理阶段列表，阶段名依次为 percent、unicode、comment、whitespace，查询模式在最前加 plus，json 模式在 percent 之后加 json；统计接口分开记录成功与拒绝数量，返回隔离副本，并发调用不丢计数。

## 运行方式
```bash
python -m pytest tests -q
```
