# GSB Bugfix Task
## 题面
服务网格改成逐跳委派令牌后，调用链上出现两类事故：下游把只读令牌换成读写令牌继续往下发，网关仍然放行；外包团队连续转委托了六层，没人知道最终操作者是谁，出事只能翻日志猜。请重写 delegation_depth_witness.py 里的 DelegationWitness：初始化接收共享密钥、最大深度和时钟偏移。签发根令牌时记录主体、受众、范围、到期时间、深度、令牌编号和是否允许再委托，并用密钥对规范化字段做签名；派生时深度加一，范围必须是父集合的子集，到期时间不得超过父令牌，父令牌禁止再委托时必须拒绝；校验时依次看结构、签名、撤销、受众、范围和到期时间，时钟偏移只允许在给定秒数内。令牌编号每次签发必须不同，链路里任一祖先被撤销就整条作废。主体为空、受众为空、范围为空、有效期非正、超过最大深度都用带错误码的异常拒绝；错误码覆盖请求非法、深度超限、范围放大、超过父级有效期、禁止再委托、签名不符、已撤销、受众不符、缺少范围、已过期和令牌格式错误。链路查询返回从根到叶的主体列表和最终深度，校验成功的声明不能带出密钥或签名原文。仓库里十五个用例全是红的，测试文件保持原样；并发从一个父令牌派生多个子令牌时，编号不能重复，每个子令牌都要能独立验过。每一跳保留自己的受众和范围，不能拿父令牌字段顶替；派生失败不能留下半张子令牌；撤销集合可以包含任意祖先编号；签名用标准消息认证码即可，不要求外部依赖，校验失败不能消耗或改写原令牌。
