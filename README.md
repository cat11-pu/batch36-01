# GSB Bugfix Task
## 题面
权限服务把策略发布和决策缓存放到一起后，撤销权限出现了延迟窗口：管理员收回了某人的导出权限，缓存里的旧允许还在继续放行；发布新策略时缓存没有按租户隔离，甲租户的新版本把乙租户的决策也冲掉；负结果不缓存，攻击者用不存在的资源把评估器打满；版本号回滚没人拦，旧策略把新规则覆盖；多个线程同时打同一个未命中键，评估器被调用十几次。请重写 policy_cache_fence.py 里的 PolicyDecisionCache：初始化接收评估器和缓存时长。发布方法按租户发布版本和策略，版本必须严格递增，同版本同策略重复发布幂等并返回零，同版本不同策略报冲突，版本倒退报回滚；判定方法接收租户、主体、动作、资源和当前时间，未命中时调用评估器，结果连同版本一起缓存，命中时标记为缓存命中；允许和拒绝都要缓存；缓存键至少包含租户、主体、动作、资源和版本，过期时间按当前时间判断；失效方法可以只清某个主体，也可以清整个租户；统计方法返回命中、未命中、评估次数的副本。最关键的是发布竞争：判定开始时记住版本，评估期间如果发布了新版本，旧结果不能写回，必须按新版本重算再返回。仓库自带十五个用例目前全部挂掉，测试文件不许改；同一个未命中键被多线程同时访问时，评估器只能被调用一次。发布时传入的策略只在评估器里使用，缓存层不得修改；未发布策略就判定要报错；缓存时长必须为正数。同一租户并发发布两个版本时只能有一个成功，另一个必须看到冲突；缓存条目要记录写入版本和过期时间，不能只按插入顺序淘汰；失效之后统计计数继续累加，不清零。

