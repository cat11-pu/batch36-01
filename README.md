# GSB Bugfix Task
## 题面
门店收银终端接入结算接口后，风控发现几笔冒名调用。会话票据里只写了终端编号，调用方从未出示终端侧签名的材料，票据被拷走就能直接用；材料声明的动作与实际接口对不上也放行；目标端点只比较路径开头，换成别的服务照样通过；材料的签发时刻取自终端本地时钟，半小时前的旧材料重放仍然有效；同一材料序号连续提交五次，五次都成功；票据过了有效期依旧能过校验，因为代码只看终端有没有入册；终端被停用后旧票据还能用到自然到期；同一把终端公钥入册两次会生成两个编号，停用一个另一个还在；验签钩子返回假，代码只写日志；材料里没有票据摘要，无法确认它服务的是哪张票据；票据与材料的终端编号不一致时没有比对；终端公钥为空串也能入册；入册接口返回的记录被外部改动后污染内部数据；签发时主体为空也照样出票；未知票据被当成有效票据直接返回主体。device_bound_token.py 的 DeviceBindingAuthority 要实现终端入册、票据签发与终端材料核验：公钥不能为空，同一公钥重复入册返回原编号，已停用的终端不能重新入册；签发时主体不能为空，票据串为高熵十六进制，并写入终端编号、受众、签发时刻与到期时刻；核验顺序为先查票据是否存在、是否到期、终端是否停用，再核材料的验签钩子、动作与端点必须和调用方声明完全一致，时刻偏离当前时间不得超过容忍窗口，材料序号在窗口内只能用一次，材料里的票据摘要必须与当前票据匹配，终端编号必须与票据一致；停用终端要让它的全部票据立刻失效；返回结果不能污染账本数据。十五条用例当前全部失败，测试不许改。

## 运行方式
```bash
python -m pytest tests -q
```
