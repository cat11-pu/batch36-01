# GSB Bugfix Task
## 题面
证书透明度上线后，审计发现签名时间戳校验形同虚设：日志编号不在白名单也接受；日志已经退役，旧时间戳仍被当成新证据；版本字段填成一也放行；时间戳落在未来，或者比证书签发早太多，没人比对；验签钩子返回假，流程继续；验签钩子抛错时原样冒到上层；日志公钥为空也被当成已知日志；叶子哈希与随证书提交的哈希不一致也被忽略；签名树头的树大小和包含证明对不上，代码只用证明里的值；签名树头的时间早于时间戳仍被采信；证明里的兄弟节点重复使用没有告警；审计路径里的哈希长度不对、包含空串，解析时直接跳过；叶索引等于树大小也去算根；单叶树的空路径被误判成坏证明；扩展字段不是字节串也通过；树大小是负数或非整数直接进了循环；根哈希对不上时返回成功。ct_inclusion_proof.py 的 CtInclusionAudit 要验时间戳与 Merkle 包含证明：日志必须在白名单且状态可用，只读与退役状态拒绝，版本只认零；时间戳不得超前，超过最大年龄拒绝；时间戳签名与树头签名分别校验，钩子异常转成签名错误码；用证书重新计算叶子哈希；树头与证明的树大小必须一致且为正整数，树头不得早于时间戳；叶索引必须落在区间内，审计路径元素必须能按十六进制解析，长度受控且单叶树允许为空；扩展字段必须是字节串且长度为偶数；按 RFC 6962 的左右拼接规则重算根，与树头根逐字比较；任一步失败给出独立错误码。多个线程同时验同一份证明要得到一致根。仓库自带 15 条断言全部未通过。

## 运行方式
```bash
python -m pytest tests -q
```
