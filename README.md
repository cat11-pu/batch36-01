# GSB Bugfix Task
## 题面
财务接入供应商电子对账单后，导入接口开始出现异常：一份带外部实体的文件让解析器去读了本机文件，另一份用实体递归把内存撑爆，还有文件在声明里换了字符集，解析出来的金额和原文对不上。旧实现直接调用标准解析器，没有关闭实体展开，也没有检查文档类型声明；命名空间只比对元素本地名，伪造前缀就能混过；金额、数量、行数没有格式约束；错误信息把整段原文带回前端。statement_xml_intake.py 中的 StatementXmlIntake 在解析前设卡。入口只收字节串，先按体积上限拒绝超大文档，再核对编码声明与实际字节是否一致，只接受不带字节序标记的 UTF-8；文档类型声明、实体声明、外部标识符、样式表指令出现任意一处就整份拒绝；正文里出现预定义实体之外的引用同样拒绝；过了检查再交给解析器，根元素须属于约定命名空间，无命名空间或未知元素都报错；根上必须有十二位单据号和允许的币种；恰好一个抬头和一组明细，明细条数有上限；每条明细的物料号不得重复，数量是规定范围内的整数，金额是两位小数并按最小单位换算；明细金额之和要与总额一致；控制字符出现在文本里也拒绝。只读计数给出成功与拒绝两项，是副本。抬头内容不能为空，根上多余属性也拒绝。这批用例十五条，逐条失败。

## 运行方式
```bash
python -m pytest tests -q
```
