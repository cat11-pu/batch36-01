# GSB Bugfix Task
## 题面
发布流水线接上签名清单后，供应链门禁误放了几批制品：签名者只按邮箱前缀匹配，任何同名账号都能签；签名者没有该通道权限也通过；清单没有签名时被当成无需校验；签名值错误只记录警告；验签钩子抛错时原样冒到流水线；证书在签名时刻还没生效或已经过期，代码却拿当前时间比对；证书现在过期但带有可信时间戳，反而被一律拒绝；时间戳时刻超出证书有效期也接受；时间戳晚于当前时刻也采信；证书序列号在吊销表里仍放行；清单搁置超过允许时长仍可发布；制品摘要与清单不一致时，代码信了清单里的值；摘要没有 sha256 前缀或长度不足也通过；清单少写一个制品、多写一个制品都能过；制品名为空或带反斜杠也过；同名制品重复出现取最后一个；版本值填成浮点数或字符串也不拦；通道名为空也更新水位；同一通道两个不同版本并发校验都成功。codesign_manifest_verify.py 的 ReleaseManifestVerifier 负责验收：签名者、密钥编号、通道三者都要精确命中；签名缺失与签名不符分开报错，验签钩子异常转换为专用错误码；用签名时刻判断证书是否有效，证书已过期时要求可信时间戳既在证书有效期内又不晚于当前时刻；吊销序列号立即拒绝；清单年龄设上限；制品名单必须与清单完全一致，名称不得为空、不得含路径分隔符，摘要必须是 sha256 前缀加六十四位十六进制字符，且与本地计算结果匹配；版本必须是正整数，通道非空；同一通道的版本必须严格递增；所有检查通过后才原子地更新通道水位，快照为副本。15 条用例目前全失败。

