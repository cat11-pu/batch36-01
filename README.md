# GSB Bugfix Task
## 题面
合规审计要求每次配置变更都可追溯，运维把流水存在单张表里，出事后发现有人用管理员账号改了两行，校验脚本只比对最后一条记录的签名，改中间或删末尾都发现不了；补记时序号重复，进程重启后链从头接上导致分叉；同一份事件因为键顺序不同算出两个摘要，中文被转义成另一种写法也导致跨系统校验失败；密钥换版后旧记录全部验不过，没有人知道断在哪一条；归档时截断文件也没有任何提示；有人把序列写成字符串，排序后顺序全乱；校验函数顺手把传入记录重排，调用方拿到的列表被改过；认证码比较用普通等于，提前返回被计时侧信道利用；检查点生成后旧记录继续增长，归档边界说不清楚。audit_seal_ledger.py 的 AuditSealLedger 负责维护这条链：构造参数给出链密钥与摘要算法，密钥不得为空，算法只接受 sha256、sha384、sha512；追加时事件必须是非空字典，键只能为字符串，浮点数与嵌套深度超过四层的值一律拒绝；序列化采用键排序、无多余空白、中文不转义的紧凑形式；记录包含递增序号、前一条记录的校验值、事件原文、事件摘要与整条记录的认证码，首条记录的前驱固定为零串。验证入口接收记录列表与可选检查点，逐条核对序号连续、前驱一致、摘要与认证码可重算，返回是否通过、长度、首个异常位置与原因码；空列表、长度短于检查点、检查点头部不一致都要给出不同原因，截断时异常位置留空；检查点只取序列与头部两个字段参与核对。记录里的序列必须是整数；验证过程只读，不得改动传入列表与字典；认证码比较使用常量时间；检查点生成后固定当时的序列与头部，后续追加不改变已发出的检查点；原因码要能区分前驱不一致、摘要不一致与认证码不一致。追加在并发下序号唯一；统计接口给出追加与验证次数，且为独立副本。

## 运行方式
```bash
python -m pytest tests -q
```
