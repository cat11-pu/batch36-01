# GSB Bugfix Task
## 题面
网关改成校验装订的在线证书状态响应后，值班同学发现几类怪事：响应状态是稍后重试，连接照样放行；响应者是一张合作方临时证书，没带状态签名用途也通过；响应里给的是另一张证书的序列号，代码取了第一条就当真；同一序列号出现两条记录，后一条被覆盖，先取到哪条全看顺序；条目为空时直接抛下标错误；下次更新时间早于本次更新时间，算出负的新鲜度还继续；本次更新时间写到未来、下次更新时间已经过去，都没有拦住；生成时间是三天前，超过本地新鲜度上限仍然采信；请求时生成的随机数没有回查，跨连接重放的响应也能用；响应签名校验失败只打日志；验签之前就提前返回成功；响应版本号不是零也接受；证书状态字段大小写写错被当成有效；单条记录缺少时间字段按零处理；颁发者自签的响应者与委托响应者走了同一条宽松分支；配置里的时钟偏移从未生效；响应者证书有效期没有覆盖生成时间；快照保留完整响应体，把响应原文带了出去。ocsp_staple_check.py 的 OcspStapler 要按 RFC 6960 做装订校验：只接受成功状态且基本类型的响应；按叶子序列号精确匹配且只允许一条；条目不得为空且每个元素是字典；吊销与未知分别给出可区分错误；当前时刻必须落在本次更新与下次更新之间并留时钟偏移，下次更新必须晚于本次更新，生成时间不得超前且不能超过新鲜度上限；时间字段不是整数按非法响应处理；随机数缺失或不一致直接拒绝；响应者要么就是颁发者本身，要么由颁发者签发、带状态签名用途且在生成时间有效；签名回调必须为真。快照记录校验次数和最近结论，失败调用也计数，且为深拷贝。这组用例眼下 15 条全失败，测试文件保持原样。

## 运行方式
```bash
python -m pytest tests -q
```
